# Проверка и публикация «11 111»

Каноническое описание процесса. Продуктовая модель и UX-правила сохраняют
свои требования к содержанию, поведению и визуальному качеству.
Объём контроля определяется изменением: это действующее правило UX-40.

## Выбор объёма

| Изменение | Достаточный контроль |
| --- | --- |
| Документация | `pnpm rules:check`, вычитка изменённых требований и локальных ссылок |
| Адрес существующей ссылки | Сборка и статический контракт, адрес и переход в затронутых локалях |
| Подпись или локальная вёрстка | Сборка и статический контракт, просмотр реального изменённого рендера в затронутых локалях и размерах |
| Поведение компонента | Его сценарий, затронутые переходы и отказные состояния, реальный вид компонента |
| Общая тема, типографика, навигация, структура | Зависимые сценарии и поверхности; полный набор при изменении всего сайта |
| Данные и формулы | План, статус, данные и статический контракт; браузер при изменении отображения |
| Правила и проверочная система | `pnpm rules:check`, `pnpm test:checks`, синтаксис workflow, изменённый путь запуска |

1440, 390, 320 px, RU/EN, клавиатура, 200% текста, темы, reduced motion и отказ
медиа — доступные сценарии. Для микро-правки проверяются затронутые свойства.
После успешного релевантного контроля завершить задачу. Продолжение требуется
при новом связанном дефекте или явном расширении задачи пользователем.
Повторное чтение всех источников и повторение завершённых проверок не входят
в обычный релиз.

## Команды и источники

`scripts/lib/check-registry.mjs` хранит исполняемый перечень.

```sh
pnpm checks:list
pnpm gate
pnpm gate --check diary
pnpm gate --check film
pnpm gate --check appearance --check light
pnpm gate:full
```

`pnpm gate` выполняет проверку правил и самой проверочной системы, плана, статуса и данных, сборку
в `site/`, статический контракт и проверку пробелов.
Этот путь не выбирает объём по имени файла, diff или исходному коммиту.

`--check` явно добавляет выбранный браузерный сценарий. Повторённое имя
выполняется один раз. `--full` добавляет все браузерные сценарии.
Оба варианта используют одну сборку `site/`.

| Имя | Что проверяет |
| --- | --- |
| `a11y` | Семантика, доступные имена, контраст, клавиатура, reflow и увеличение текста |
| `browser` | Основные маршруты, меню, архив, медиаконтролы и состояния страницы |
| `appearance` | Авто/ручная тема, смена времени и сохранение темы |
| `film` | Данные монтажа, настоящее воспроизведение, звук, перемотка и отказ видео |
| `light` | Солнечная модель, прогноз, достоверность и отказные состояния |
| `journey` | Связь меню, календаря, исторического заезда и дневника |
| `diary` | Появление при прокрутке, подвал, раскрытие, hover и клавиатура виджета |
| `screenshots` | Реальные кадры названных сценариев, геометрия и переполнение |

`CHECK_ENGINES=chromium` или `CHECK_ENGINES=webkit` ограничивает движки.
`BROWSER_REGRESSION_ENGINES` и `RIDE_FILM_ENGINES` сохраняются для существующих
CI-команд и имеют приоритет. Виджет и контрольные кадры имеют отдельные\nсценарии только в Chromium. Неизвестные параметры и движки, а также пустой
фильтр скриншотов завершаются ошибкой.

Старые самостоятельные команды доступности, общей регрессии и кадров
сохраняют сборку `preview/` при вызове без каталога.
Переданный каталог всегда используется напрямую.
Для публичного маршрута адрес задаётся явно:

```sh
node scripts/journey-browser-check.mjs --url 'https://11111.life/?release=COMMIT'
```

Позиционный каталог не переключает тест на production.

## CI и публикация

`.github/workflows/pages.yml` публикует `main` после `pnpm gate`.
Полный набор не является его зависимостью. Плановый запуск тем же путём
обновляет прогноз пыли; обычная правка не ждёт внешнего прогноза.

`.github/workflows/quality.yml` — отдельный ручной полный набор.
Он включает Chromium, WebKit и воспроизведение на macOS.
Нативный медиастек Safari проверяется на macOS; Linux WebKit проверяет
доступность, темы и геометрию.
Workflow имеют разные группы concurrency и не отменяют друг друга.

При имеющемся разрешении на релиз: включить только относящиеся к задаче файлы,
сохранить коммит, отправить его, дождаться публикации именно этого коммита,
один раз проверить изменённое место на публичном адресе с новым release.
Завершённые локальные проверки не повторяются целиком ради публикации.

## Доказательства качества

Автоматические проверки подтверждают только названные свойства.
Кадр без просмотра не доказывает композицию. Зелёный тест не является
человеческой приёмкой. При визуальном изменении обязательно посмотреть
реальный рендер и сверить его с запросом или принятой версией.
Требования к приёмке нового направления сохраняются в AGENTS.md и design-evals.md.

Различать: изменено в коде, проверено автоматически, просмотрено в рендере,
принято пользователем, опубликовано. Указывать только подтверждённые состояния.
Обычные действия в уже разрешённой задаче не создают дополнительного
согласования — это действующее правило UX-документа.

## Диагностика

Runner показывает вывод каждого шага, результат и время.
`artifacts/gate/automated/checks-report.json` содержит отчёт запуска.
Ошибка останавливает выбранный набор на конкретном шаге; таймаут ограничивает
зависание. Отдельная CI-задача явно отмечается в отчёте.

`pnpm test:checks` проверяет короткий путь без браузеров, одну сборку, выбор
сценария, отказ на опечатках и HTTP Range-запросы тестового сервера.
`pnpm rules:check` проверяет перечень, команды и локальные ссылки.

Аудиты с датой описывают свой коммит и не вводят требований к новым релизам.
Незаконченные локальные разработки сохраняются; проверяется сборка того же
checkout, а не чужой каталог preview.

## Ревизия технического долга · 8 октября 2026

| Долг | Исправление |
| --- | --- |
| Микро-правка и обязательный полный цикл в соседних разделах | Масштаб определяется UX-40; полный контур новых паттернов явно отделён от микро-правок |
| README требовал воспроизведение обоих движков перед каждой публикацией | Требование отнесено к отдельному полному набору |
| Обязательный UX-документ оставался только в незакоммиченной рабочей копии | Включён в нормативный набор и проверку ссылок |
| Сборка в site, затем повторные сборки preview внутри тестов | Registry передаёт один каталог всем сценариям |
| Проверки заменённого звукового блока и старой карты | Три неиспользуемых сценария удалены, историческое описание помечено |
| Опечатка движка или пустой фильтр могли дать неполный PASS | Строгая проверка параметров и количества выбранных сценариев |
| Долгий шаг скрывал весь вывод до окончания | Потоковый вывод, время каждого шага, отчёт текущего запуска и таймаут |
| Тестовый сервер неправильно обслуживал suffix/выходящие за границы Range-запросы | Корректные 206/416, HEAD, быстрый отказ без сборки и закрытие соединений; отдельные тесты |
| Каталог в аргументе journey мог означать публичную проверку | Production выбирается только явным --url |
| Два процесса публикации могли вновь смешаться | Короткие тесты выбора и проверка разделения workflow входят в обычный gate |

Оставшийся долг вне процесса: в основном JS/сборщике сохранились части
старого звукового блока; их удаление относится к отдельной чистке исходника.
Общая браузерная регрессия и перечень кадров крупные; они уже ограничены
сценариями, отдельными процессами и таймаутами, но дальнейшее разделение на
модули облегчит сопровождение. Эти пункты не требуют расширять визуальную
микро-правку и не являются зависимостью публикации.
